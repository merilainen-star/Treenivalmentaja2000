# Proportional phases, recorded heart rate and pace

The phase chart now uses horizontal length rather than equal slots. For timed plans the width
is duration: 720 seconds takes sixty times the width of 12 seconds. A distance stage with a
target pace uses distance × pace and labels the time axis as estimated. All-distance plans with
missing pace use metres; a mixed plan missing duration/pace explicitly falls back to labelled
stage order. No missing duration is silently guessed. Previous/Next controls keep short stages
accessible without imposing a misleading minimum bar width.

After a run, a 220 dp chart overlays measured HR samples on translucent phase bars. The line has
a contrasting outline and its own labelled bpm scale, independent of bar height; phase height
still denotes type, not measured intensity. Selecting a stage shows its elapsed duration and
available HR range and measured lap-average pace. Missing samples and gaps over 15 seconds break the line. No smoothing or
curve synthesized from lap averages is used.

The second curve shows measured pace in min/km, with a separate right-hand scale (faster at the
top) and amber colour. `Vaiheet`, `Syke` and `Vauhti` filter chips independently toggle the three
layers; selection and lap metrics remain available when a layer is hidden. Toggle state survives
screen recreation. The average shown for a selected lap uses that lap's active timer time divided
by distance, exactly as the measured laps supplied to AI; it is never an arithmetic mean of pace
samples or based on planned duration. Missing lap distance produces an explicit unavailable label.
Zero speed is retained as measured zero, but breaks a min/km curve because its pace is infinite.

FIT record field 73 (`enhanced_speed`, uint32 / 1000 m/s) takes precedence over field 6 (`speed`,
uint16 / 1000 m/s); an invalid enhanced value falls back to valid standard speed. Invalid fields
remain null, not zero. Both streams share the same record timestamps and time origin, including
compressed timestamp rollover. See the [official record profile](https://github.com/garmin/fit-java-sdk/blob/main/src/main/java/com/garmin/fit/RecordMesg.java).

Both record timestamps/heart rate and lap start/elapsed fields are read from the same original FIT
file. A shared origin keeps samples and boundaries aligned; active timer durations are never
summed to position laps, so pauses retain their width. Normal and compressed timestamp records
and either endian are supported. Field numbers and compressed rollover follow the
[Garmin FIT protocol](https://developer.garmin.com/fit/articles/fit-protocol/fit_protocol.html)
and [official lap profile](https://github.com/garmin/fit-java-sdk/blob/main/src/main/java/com/garmin/fit/LapMesg.java).
Only relative elapsed seconds, HR/speed values and lap boundaries are retained; no location is stored.

Equal ordered lap/stage counts allow names/phase colours to be associated by position.
The everyday explanation of pairing and bar height was removed at the owner's explicit request;
the actual matching/overlap guards remain. This is not proof of Guide execution. Different counts show neutral numbered
laps. Overlapping or missing boundaries are not guessed; HR can be shown alone. If no recorded
timeline exists, the planned timeline remains labelled as planned and HR absence is stated.

Room v19 adds only `intervals_run_traces` (activity id, JSON, fetched timestamp), generated by KSP
with an additive 18→19 auto-migration. Both historical v17 variants still use the explicit
17→18 migration. A successful empty trace records absence, while failed HTTP fetches remain
retryable. A trace missing from a previously fetched run triggers bounded FIT backfill; if its
original file is now absent or unreadable, existing lap summaries are retained. Disconnect clears
traces and fetch markers under the existing connection-generation guard. The raw FIT is discarded.
Trace JSON is decoded on the repository's injected `metricsDispatcher` (Default in production),
keeping long recordings off the UI thread. Scheduler-driven repository/ViewModel tests inject
their test dispatcher so `advanceUntilIdle()` also waits for these metrics.

The pace addition keeps Room at v19. JSON cache format v2 adds speed samples; old JSON decodes
with version 1 and an empty speed list. A streaming metadata check schedules bounded refetch of
old traces, even if laps and HR are already cached. Successful absence is recorded at version 2
to avoid repeated downloads. Network failures leave the old version retryable. If the source file
has disappeared, the existing HR/phase trace and lap summaries are preserved. Raw speed samples
remain local and are not added to AI requests.

Validation covers width ratios and hit testing, estimated/missing pace, elapsed pauses,
compressed timestamp rollover, big endian records, missing HR, round-trip persistence, HTTP
backfill/cache/disconnect, migrations and UI stage selection. Screenshot fixtures are synthetic
and labelled as example data; they are not measurements from the user's workout.
